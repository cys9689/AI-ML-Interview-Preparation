## Key Idea

Use BFS to process each level from left to right. The right side view contains the last node value at each level, even when that node is a left child.

At the start of each while iteration, snapshot `level_size = len(queue)`. Process exactly that many nodes because children added during this iteration belong to the next level.

## Final Code Written During Practice

```python
from collections import deque

def rightSideView(root):
    if root is None:
        return []
    queue = deque([root])
    result = []
    while queue:
        level_size = len(queue)
        for i in range(level_size):
            node = queue.popleft()
            if i == level_size - 1:
                result.append(node.val)
            if node.left is not None:
                queue.append(node.left)
            if node.right is not None:
                queue.append(node.right)
    return result
```

## Complexity

- Time: O(n). Every node is enqueued, dequeued, and processed once. The inner loops across all levels total n iterations.
- Auxiliary queue space: O(w), where w is maximum tree width; worst case O(n).
- Output space: O(h), where h is tree height, because one value is saved per level.

## Mistakes Caught

- Right side view means the rightmost node at each level, not only right children.
- The live queue length cannot identify the last node of a level because next-level children are being added.
- `level_size` is an integer; do not call `len(level_size)`.
- Pop each node exactly once and save it as `node`; append `node.val` to the result.
- Process root inside the same BFS loop so its value is included.
- Nested loops do not automatically imply O(n * w); count total node visits.
- In the sparse-tree example with nodes 1, 2, and 5, the answer is [1, 2, 5], not [1, 2, 3].
