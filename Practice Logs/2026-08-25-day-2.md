# Day 2 Practice Log - Top K Frequent Elements

Date: 2026-08-25

## Topic

Hash Map + Sorting

## Problem

Top K Frequent Elements

Given an integer array `nums` and an integer `k`, return the `k` most frequent elements.

Example:

```text
nums = [1, 1, 1, 2, 2, 3]
k = 2
output = [1, 2]
```

## Approach Practiced

Sorting version:

1. Build a frequency map: `num -> count`.
2. Convert the map into a list of pairs: `(num, frequency)`.
3. Sort pairs by frequency in descending order.
4. Take the first `k` elements and return only the numbers.

## Final Code

```python
def topKFrequent(nums, k):
    freq = {}
    for num in nums:
        if num in freq:
            freq[num] += 1
        else:
            freq[num] = 1

    count_list, result = [], []

    for key, val in freq.items():
        count_list.append((key, val))

    count_list.sort(key=lambda pair: pair[1], reverse=True)

    for i in range(0, k):
        result.append(count_list[i][0])

    return result
```

## Complexity

Let:

```text
n = len(nums)
m = number of unique elements
```

Frequency map:

```text
O(n)
```

Sorting unique elements:

```text
O(m log m)
```

Taking top `k`:

```text
O(k)
```

Overall time complexity:

```text
O(n + m log m + k)
```

Usually simplified to:

```text
O(n + m log m)
```

Worst case when `m = n`:

```text
O(n log n)
```

Space complexity:

```text
O(m + k)
```

Worst case:

```text
O(n)
```

## Mistakes Caught

- Default tuple sorting sorts by the first element first, not by frequency.
- Need `key=lambda pair: pair[1]` to sort by frequency.
- `range(0, k - 1)` misses one element; use `range(k)`.
- Append `count_list[i][0]`, the element, not the whole pair.
- Sorting makes the solution `O(n log n)` in the worst case, not `O(n)`.
